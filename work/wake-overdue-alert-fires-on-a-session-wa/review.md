## the change (unchanged this round)

Two root causes, both fixed test-first. `drainWakes` no longer holds `draining` across `$.prompt.submit`: submits run fire-and-forget on their own serial `submitWakes` chain, so the poll's `finally` clears `draining` at once and the next poll keeps taking — a held host submit can no longer starve `take_wakes`. `presence_idle` is withheld while a subagent runs: `turn.start`/`turn.complete` track `agentId` in the `running` set and set `mainEnded` on the main turn's complete; idle fires only when `mainEnded && running.size === 0`. While waiting, a `presence_doing { summary: "waiting on a background agent" }` heartbeat fires every `STALE_REFRESH_TICKS = 60` poll ticks (~180 s at 3 s) against the 600 s stale-turn clock, and `presence_doing` resets `thinking_since` server-side, so the unchanged `Wake.report_overdue` guard reads the seat as busy. `session.end` clears `running`. The two new tests cover both halves (a hung submit doesn't stop the next poll from taking; a main turn ending with a subagent running is not idle), and the stale-refresh characterization test asserts exactly one heartbeat across 60 ticks then `presence_idle` on subagent complete.

## non-blocking follow-ups (replace the prior review's set — all filed, held)

1. **Not proven live (#546, med).** The fix is green under the gate and sound by reading the server, but the mod's AGENTS.md asks it be proven on a live seat: launch a citizen, background a subagent, confirm `turn` events carry `agentId` live (so the running-set path engages) and the seat stays off the overdue clock.

2. **Wakes queued behind a held submit are lost on session end (#547, high, held).** `take_wakes` deletes the server row; `submitWakes` queues the text onto the in-memory `submitting` chain. If the session ends (crash, abort, `/clear`) while a submit is held, the chain is abandoned and those wakes never reach `put_back_wakes` — silent loss, no server row to report stale. The old code risked only the one wake mid-submit; this change widens the window to every wake that arrived during the held submit. Fix: keep not-yet-submitted wakes in a module-level list and `put_back_wakes` them in the `session.end` hook next to `running.clear()`. Skipping `take_wakes` while a submit is pending is rejected — wakes would sit untaken past the overdue window and bring back the false alarm.

3. **A subagent that never sends `turn.complete` leaves the seat permanently busy (#545, med, held, blocked by #547).** If a background subagent crashes or aborts without `turn.complete`, its `agentId` stays in `running` until `session.end`, so `presence_idle` is never declared and the ~180 s heartbeat fires forever — the opposite false state from the bug this change fixes. Fix: on a new main `turn.start`, or after a bound on `waitTicks`, drop stale entries from `running` and declare idle; also reset `mainEnded` and `waitTicks` in `session.end`.

4. **`waitTicks` phase drifts across waits in a long-lived session (#548, low, held, blocked by #547).** `waitTicks` is module-level, only incremented, never reset, so a second wait's first refresh fires at tick `60 − N%60` rather than 60. Non-functional — the max refresh gap stays under 180 s against the 600 s clock. Fix: reset `waitTicks = 0` on main `turn.start`, with a two-waits test.
